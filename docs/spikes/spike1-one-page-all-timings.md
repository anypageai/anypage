# Spike 1：一個頁面，所有時間性（Windows）

2026-10-24。狀態：**Windows 部分完成並量測**；Android、Linux、Web、macOS、iOS 尚未做。對應 [ARCHITECTURE.md](../ARCHITECTURE.md) 第 3 節與第 15 節的第 0 階段 spike 1。

## 做了什麼

**核心 `crates/anypage-core`**，不依賴任何 GPU API、平台或檔案格式：

- **計算圖** `graph.rs`：輸入格、串流格（追加或最新者勝，有界緩衝與背壓）、導出格（行內或非同步算子）。需求驅動求值，髒標記沿依賴傳播，輸入一變就取消計算中的舊任務，其他執行緒的產出只在 `commit` 時合批進圖。
- **工作池** `pool.rs`、**可取消的 tile 佇列** `sched.rs`、**鏡頭** `camera.rs`、**tile 定址** `tiles.rs`。
- 14 個單元測試，加一支 10⁵ 與 10⁶ 格的基準測試 `examples/graph_bench.rs`。

**Windows 殼與示範頁面 `apps/spike1`**：

- winit 視窗，wgpu 依序嘗試 DX12、Vulkan、GL（架構第 14.6 節的退路），可用 `ANYPAGE_BACKEND` 強制。
- 一個合成器：tile、面板、HUD 共用一條四邊形管線，GPU 算子另一條。
- 每幀排程：預算 10 ms，優先序為操作、拉式串流、推式串流、非同步、靜態；只求值可見的面板；沒有可見變化就不重畫；閒置時 0 幀。

示範頁面把五種時間性放進同一張圖：

| 時間性 | 內容 | 在圖上是什麼 |
|---|---|---|
| 靜態 | 引擎自己計算的分形 tile，可深度縮放 | 參數導出格；它的版本是 tile 的快取鍵。tile 在 24 條工作執行緒上光柵，離開視口就取消，參數變了舊 tile 先頂著 |
| 拉式串流 | GPU 動畫（WGSL）與 CPU 軌道動畫 | 依賴時間輸入格 `t` 的導出格；只在可見時每幀求值 |
| 推式串流 | 即時行情圖、模擬逐字輸出 | 兩個串流格，生產者在其他執行緒以不固定速率推送，偶爾連發 |
| 非同步 | 6 個 CPU 任務 | 非同步導出格；完成前顯示進度，完成時合批成一次 commit |
| 操作 | 拖曳、縮放、滑桿、按鈕、鍵盤 | 對輸入格下指令；色相一個輸入格同時影響 tile、圖表、GPU 動畫與 CPU 動畫 |

## 怎麼跑

```powershell
cargo run --release -p spike1                    # 互動模式
cargo run --release -p spike1 -- --bench         # 20 秒腳本量測，報告寫進 bench-results/
cargo run --release -p anypage-core --example graph_bench
cargo test --workspace
```

操作：拖曳平移、滾輪縮放、空白鍵 串流開關、A 動畫開關、J 執行任務、C 取消、1 / 2 調迭代、R 貼合整頁、H 隱藏量測面板、Esc 離開。

## 結果

機器：Ryzen 9 5950X（32 執行緒）、RTX 3090、Windows 11、DX12、vsync、視窗 2400×1500 實體像素。

**頁面量測**（`--bench`：縮放進分形 6 秒、改參數並啟動任務、平移右欄 5 秒、全部靜止 3 秒、恢復）：

| 指標 | 結果 |
|---|---|
| 渲染幀數 | 19.5 秒內 885 幀；有可見變化時穩定 60 fps |
| 幀間隔 | p50 16.66 ms，p95 17.09 ms，p99 17.51 ms |
| 每幀 CPU 時間 | p50 1.99 ms，p95 6.66 ms，p99 9.63 ms，最大 15.3 ms |
| 操作到上屏 | p50 16.4 ms，p99 17.1 ms，約一幀 |
| 推式串流資料到上屏 | p50 23.7 ms，p99 33.3 ms |
| 非同步結果到上屏 | p50 19.4 ms，最大 27.3 ms |
| tile 請求到上屏 | p50 48.5 ms，p95 81.6 ms |
| 單張 tile 光柵時間 | p50 1.7 ms，p95 16.2 ms |
| 靜止的 3 秒 | **0 幀**，迴圈只醒來 1 次 |
| 串流 | 1,367 筆，丟棄 0 筆 |
| 記憶體 | 約 430 MB（含 21 MB 中文字型與 tile 快取） |

**計算圖基準**（`graph_bench`，release）：

| 情境 | 結果 |
|---|---|
| 10 萬格，改一個輸入，波及 5,049 格 | 標髒 0.47 ms，重算 1.63 ms |
| 100 萬格，同樣波及 5,049 格 | 標髒 0.34 ms，重算 2.09 ms |
| 什麼都沒變時對所有出口格呼叫 demand | 10 萬格 0.03 ms；100 萬格 0.31 ms |
| 第一次完整求值 | 10 萬格 37 ms；100 萬格 370 ms |
| 最壞情況：10 萬格長鏈，每格都變 | 29 ms，超過一幀 |

## 對照架構的主張

| 主張（第 3 節） | 這次的證據 |
|---|---|
| 不同時間性的內容可以在同一個頁面、同一個迴圈裡一起跑 | 五種內容同時在畫面上，幀間隔 p99 17.5 ms |
| 沒有變化就是 0 fps | 靜止 3 秒 0 幀；閒置時只有視窗標題每秒更新，不渲染 |
| 增量重算的成本跟變化量成正比，不跟頁面大小成正比 | 10 萬格與 100 萬格局部變動的成本幾乎相同 |
| 一個輸入沿圖傳播到所有種類的內容 | 改色相後，tile、圖表、GPU 動畫、CPU 動畫在同一幀一起換色 |
| 串流合批、不卡頓 | 行情連發 20 至 60 筆時合成一次 commit；未丟資料 |

## 和架構不一致或還沒做的地方

- 光柵用 tiny-skia、字形用 fontdue，不是架構寫的 vello_cpu 與 parley。理由是 API 穩定；它們只出現在殼裡，換掉不影響核心。
- wgpu 用 26，上游已到 30。升級是另一個獨立步驟。
- 圖層目前是一個面板一張 texture，還不是從依賴關係自動導出的分層（第 3.3 節）。
- 最壞情況的長鏈全部重算 29 ms，超過一幀。之後需要提前截斷（值沒變就不往下傳）或跨幀分批求值。
- 延遲量到 `present()` 返回為止，不含顯示器掃描時間。
- 使用者按取消的任務會以「錯誤：已取消」完成，統計上算完成；只有因輸入改變而取消的才算進「取消」。
- 還沒有：腳本 VM（spike 2）、能力代理、語義埠、頁面包、PDF 資源格（`anypage-pdf` 暫時排除在 workspace 外）。
- 只在 Windows 上跑過。截圖時 HUD 的 fps 會短暫下降，是 PrintWindow 擷取的干擾，以腳本量測為準。
